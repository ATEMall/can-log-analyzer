## 二、需求拆解

### R9 深色模式（对应 TD-6 / PRD §5.3，P0）

- **功能**：浅色/深色两套主题；跟随系统（`nativeTheme`）+ 手动切换（菜单 + 设置页）；选择持久化至 settings.json（复用 R6 通道），启动恢复。
- **技术约束**：所有颜色收敛为 CSS 变量设计令牌（`--bg`/`--ink`/`--red` 等），**禁止组件内散落硬编码色值**（现有硬编码色一次性迁移）；切换不刷新窗口；曲线色板、位布局色块、信号勾选色三者在两套主题下保持一致语义。
- **UI 规格**：深色 = 深灰底 + 品牌红 `#C62828` 强调（PRD §5.3）；告警/异常红、正常绿的中国习惯配色在深色下提高对比度；图表（recharts）轴/网格/背景随主题。
- **验收**：① 全部视图（报文表/信号表/曲线/位布局/DBC/统计/抽屉）逐屏走查无「白块残留」；② 跟随系统切换即时生效；③ 重启后主题恢复；④ 现有 163/163 回归 + 新增主题单测通过；⑤ 截图对照（浅/深 × ≥5 视图）。

### R10 可折叠布局与状态记忆（对应 UI-001/UI-007，P0）

- **功能**：左侧 DBC 面板可折叠为一列窄条（默认展开宽约 25%，可拖拽 15%–45% 区间调节）；折叠/宽度/右侧活动 Tab/树展开状态全部持久化。
- **技术约束**：拖拽最小步进 4px；宽度与状态写入 settings.json；面板折叠动画 ≤150ms，拖拽期间用 transform 不触发布局抖动；1M 帧数据加载中折叠不丢虚拟滚动状态。
- **验收**：① 折叠/展开/拖拽顺滑，无内容溢出；② 重启后布局 100% 恢复；③ 拖拽过程中报文表滚动帧率目测无卡顿；④ 单测覆盖状态持久化读写。

### R11 全局搜索 + 时间轴总览（对应 UI-002 / FR-VIS-002，P1）

- **功能（全局搜索）**：顶部单一搜索入口，统一检索消息名/信号名/CAN ID（十进制+十六进制）/DID；Enter 定位首个结果，结果高亮 + 计数（如 12 hits）；Ctrl+F 唤起、Esc 清除；搜索范围可选（当前视图/全部视图）。
- **功能（时间轴总览）**：报文日志与曲线视图底部全局缩放条（minimap）；显示全时间跨度 + 当前视窗；拖拽平移、滚轮/双击缩放；总览条同步渲染各 ID 的密度热条（降采样到 ~2000 桶）。
- **技术约束**：搜索走主进程索引（首建 ≤200ms @1M 帧，增量日志无重建）；时间轴桶聚合在主进程计算，IPC 只传桶数组；两个视图共享同一时间窗状态。
- **验收**：① 1M 帧日志搜索首响应 ≤300ms（本机）；② 搜索定位后表格滚动到目标帧且高亮可见；③ 总览拖拽缩放流畅、与主视图时间窗双向同步；④ 密度热条与真实帧分布抽样核对一致。

### R12 总线负载与错误帧统计（对应 FR-VIS-003/004，P1）

- **功能（负载）**：统计面板显示逐秒负载率曲线（%）、平均/峰值负载、按帧周期统计 + 抖动（jitter = 实测周期 − DBC `GenMsgCycleTime`，显示均值/最大/超差帧占比）。
- **功能（错误帧/总线状态）**：识别 ASC/BLF 中的错误帧与错误计数事件，统计面板展示错误帧总数/分类、Error Active/Passive/Bus Off 时间线标记；错误帧支持点击跳转报文表对应时刻。
- **技术约束**：逐秒聚合主进程流式计算（复用 R2 分块管道，不二次全量回传）；周期/抖动按消息 ID 分组，O(n) 单遍；统计结果可导出 CSV（沿用 R7 导出通道）。
- **验收**：① 用 `TestExample/` 现有日志人工核对 3 个消息的周期均值/抖动与脚本计算一致（容差 ±0.1ms）；② 构造含错误帧的样例日志验证分类与跳转；③ 1M 帧统计计算 ≤2s 且不阻塞 UI；④ 周期超差帧可筛选联动报文表。

### R13 多 Y 轴曲线与降采样复核（对应 FR-VIS-001 / §5.4，P1）

- **功能**：曲线视图支持多 Y 轴——左轴/右轴，按量纲自动分组（同量纲共享轴），手动可改；轴颜色与对应信号曲线颜色一致。
- **技术约束**：保持现有 1M 点 min/max 保真降采样（§5.4：渲染 ≤2s）；新增轴不引入全量重绘（增量 append 路径保持）；图例点击仍可逐信号显隐。
- **验收**：① ≥3 信号（不同量纲）双轴显示正确、缩放/平移联动；② 1M 点 × 双轴渲染 ≤2s（本机）；③ 降采样保真抽样核对无尖峰丢失；④ 回归通过。

### R14 错误上报与诊断日志（对应 TD-7，P1）

- **功能**：应用内诊断日志——主进程按天滚动记录关键事件（文件加载/解析错误统计/IPC 异常/渲染进程崩溃，路径 `%APPDATA%/can-log-analyzer/logs/`）；「帮助 → 打开诊断日志」直达；错误报告抽屉新增「一键复制诊断信息」（版本/日志时长/错误摘要，脱敏不含用户数据内容）；日志保留 7 天自动清理。
- **技术约束**：日志级别 info/warn/error；渲染进程 `window.onerror`/`unhandledrejection` 上报主进程统一落盘；写入异步不阻塞；日志文件不含 CAN 报文数据内容（仅计数与错误原因）。
- **验收**：① 人为触发解析错误/渲染异常，日志有对应记录且含时间戳与堆栈摘要；② 7 天清理生效（可用假日期单测验证）；③ 复制诊断信息可直接粘贴定位问题；④ 性能无回退。

## 四、通用开发要求（DoD，全部需求适用）

1. **分支与提交**：`feature/v2.2-<需求号>` 分支开发；提交信息 `feat(v2.2): ...` / `fix(v2.2): ...`；合并回 main 前自测全量回归。
2. **测试**：每个需求附 vitest 单测（组件测试 + 主进程逻辑测试）；交付时全量回归 ≥163/163 且不回退；cantools 对拍保持 0 不一致（R12 改动不得触碰 signalDecode.js 解码路径）。
3. **性能红线**（PRD §5.4）：1M 帧加载 ≤5s；曲线 1M 点 ≤2s；任何新计算走主进程/流式，UI 主线程响应间隔 <200ms；违反红线按 P0 缺陷返工。
4. **UI 规范**：遵循 PRD §5.3 主题令牌（禁止新硬编码色值）；告警红/正常绿；所有耗时操作进度 + 可取消（UI-004）；空态引导（UI-005）。
5. **交付流程**：代码推送到 main 后在对应 Issue 评论交付说明（改动清单 + 测试证据 + 截图）；**禁止只评论不推送**；CHANGELOG.md 与 README 同步更新（发版批次一起，但功能条目交付时先写入 [Unreleased]）。
6. **验收流程**：PM 按各需求验收标准逐条复核（代码走查 + 实测 + 截图证据）→ 通过后关闭 Issue；不通过在 Issue 列返工条目。
7. **文档**：影响使用方式的功能（搜索/统计/诊断日志）须更新 README 使用手册章节。
