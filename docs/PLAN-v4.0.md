## 三、需求拆解

### B1 子任务（鸟瞰）

#### T1 ISO-TP 重组（`electron/isotp.js`，P0）

- **功能**：按 ISO 15765-2 重组 UDS 报文——Single Frame、First Frame（长度域）、Consecutive Frame（序号 + **序号回绕**）、Flow Control（CTS / Wait / Abort）
- **约束**：走主进程流式管道（复用 R2 分块），不二次加载全量帧；连续帧间隔 >1s 判重组中断，已重组部分进 R4 容错通道记录（**禁止静默丢弃**）；重组结果带元数据（源/目标 ECU 地址、服务 ID、总长度、重组耗时）
- **必过用例**：BMW MSD80 样本中的 **137B 长响应**（2 × FF + ≥8 × CF）
- `0x140` 为**扩展帧（29 bit）**，与 `0x7e0/0x7e8`（UDS）、`0x6f1/0x612`（KWP2000）需区分对待

#### T2 UDS 服务解析（`electron/uds.js`，P1）

- **功能**：SID 识别与语义化展示——0x10 会话控制、0x19 DTC、0x22 读 DID、0x27 安全访问、0x2E 写 DID、0x11 ECU 复位；子功能字节、DID（2 字节）拆分；DTC 按 3 字节组 + 故障类型编码解析；**负响应 0x7f 后缀 NRC 需单独归类并标注**
- **约束**：KWP2000 帧（0x6f1/0x612）本轮**不解析但不得报错丢弃**，须计入容错统计

### B2 子任务

#### T3 A2L 解析（`electron/a2l.js`，P0 / FR-DB-007）

- **功能**：解析 ASAP2（ASAM MCD-2）文件，提取 MEASUREMENT、CHARACTERISTIC、COMPU_METHOD（`LINEAR`/`TABLPARM`/`RATIOFUNC`/`TEXTTABLE`）、`AXIS_PARM`/`AXIS_DESCR`
- **约束**：
  - **无第三方对拍基线**（ASAP2 没有 cantools 等价物），验收只能靠 ASAP2 官方 Demo 自证
  - 必须支持 `INCLUDE` 与**嵌套 INCLUDE**（`TEST_Nested_Includes.a2l` 是专门用例）、文件 fragment 拼接、`/begin ... /end` 配对校验、`#include` 相对路径
  - 容错：未识别 BLOCK 跳过并计数，**不得因单个未知 BLOCK 中断整体解析**（沿用 R4 原则）
  - 大文件（V171 242KB）加载 ≤5s

#### T4 UDS 请求/响应配对视图（P1 / FR-DECODE-004）

- **功能**：按 CanIf 地址（如 0x7e0 ↔ 0x7e8）配对请求与响应，展示成对的服务交互；支持按 ECU 地址过滤
- **UI**：沿用现有面板视觉与主题令牌，新增页签或抽屉（开发侧出视觉稿后 PM 复核空态/加载态）

### B3 子任务（依赖用户素材）

#### T5 XCP 解析（`electron/xcp.js`，P1 / FR-DECODE-005）

- **功能**：A2L 关联 + DAQ 解包（Event → ODT → DAQ 列表）+ 标定量实时值与曲线
- **约束**：XCP over CAN（0xBD）优先，XCP on Ethernet 二选一先做；DAQ 时间戳按 XCP 内部时钟；**素材到位前不得开工**

### ⚠️ 关键坑 1：素材是 candump 文本，不是 ASC/BLF

PM 实测 `.cap` 首行：

```
1775602023.192750 0x140 0a0a000000000000
1775602024.055013 0x6f1 12021a80
```

三列 = **epoch 秒（6 位小数）+ `0x` CAN ID + 数据 HEX**。现有 `asc.js`/`blf.js` 均不认。

处置二选一，**开发侧在 B1 第 1 个工作日回帖确认选哪个，PM 默认倾向 ①**：

- **① 新增 `electron/cap.js`**（candump 解析器），与 ASC/BLF 并列为第三日志源，复用 R2 分块管道；时间基准归一化为相对会话起始秒，与现有报文表字段对齐
- ② 写一次性脚本把 `.cap` 转 `.asc` 入库，解析器不动

### ⚠️ 关键坑 2：A2L 没有 cantools

数值正确性无法走第三方对拍。DoD 已写死自证方式（手工 grep 计数 + 手工换算抽查），见 §五。

### ⚠️ 关键坑 3：XCP 素材外部依赖

`TestExample/roadmap_v3x/README.md` 已记录「XCP 测量日志（DAQ 抓包）未找到公开源」。**用户 2026-10-04 确认可提供**，请在本 Issue 评论告知到位时间，B3 随之启动。

## 五、通用开发要求（DoD，沿用 v2.2 基线）

1. **分支与提交**：`feature/v4.0-<子任务号>`；提交 `feat(v4.0): ...` / `fix(v4.0): ...`；**合并回 main 前须在 Issue 评论提交完整自测证据**（回归数 + 专项用例数 + 构建结果），禁止未复核即合 main（#20 流程约束）；合并用 `Closes #N` 自动闭环。
2. **测试**：每子任务附 vitest 单测；全量回归 ≥ **329/329** 不回退；cantools 对拍保持 0 不一致——但 **A2L/XCP 路径不参与 cantools 对拍**（无对拍基准），UDS 另建对拍脚本（见 §六验收①）。
3. **性能红线**（PRD §5.4）：1M 帧加载 ≤5s；**ISO-TP 重组走主进程流式管道，禁止渲染进程全量重组**；UI 主线程响应 <200ms。
4. **UI 规范**：沿用主题令牌，禁止新增硬编码色值；新面板复用现有 DBC/信号面板视觉；耗时操作进度可取消。
5. **交付流程**：推送后在 Issue 评论交付说明（改动清单 + 测试证据 + 截图）；禁止只评论不推送；CHANGELOG 交付时先写入 `[Unreleased]`。
6. **文档**：影响使用方式的功能须更新 README 使用手册章节。
